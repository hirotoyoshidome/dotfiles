# 決済バッチ遅延の調査について

先月の障害で、夜間の決済バッチが朝9時を過ぎても終わらず、経理チームから問い合わせが来た。その日は担当者が休暇中で、復旧まで半日かかった。

当初はDBのロック待ちが原因と報告したが、これは誤りで、実際は外部の為替レートAPIの応答遅延が原因だった。

## 整合性担保観点

為替レートAPIは応答時間の保証がなく、設計が不十分である。API提供チームはタイムアウトを短くし、リトライ回数を3回に減らすべきだ。

## 対応

部長の判断で、レート取得を前日夜に前倒しする方式にした。この変更は現在レビュー中である。

この資料は一時資料なので、リポジトリにはcommitしない。

## 対象外とした事項

- 決済バッチ全体の並列化
- 監視ダッシュボードの刷新
