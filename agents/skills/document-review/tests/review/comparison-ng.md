# ジョブ実行基盤の移行先

現在、旧基盤では37件のジョブが動いている。

移行先の候補はA案(マネージドのワークフローサービス)とB案(自前のKubernetes CronJob)である。A案は運用負荷が低いが従量課金で、ジョブが増えると費用がかさむ。B案は費用を抑えられるが、クラスタの運用が必要で、障害時の切り分けも自分たちで行う。どちらも既存ジョブの書き換えは必要で、A案のほうが書き換え量は多い。

旧基盤は場当たり的に作られたもので、構成がひどい。

移行作業には、どの環境でもデータが消える恐れがある。

優先順位は、1. 経理部門からの要望、2. 書き換え工数、3. 月額費用の順とする。

推奨はB案である。

リスクとして、移行中にジョブが二重実行される可能性がある。
