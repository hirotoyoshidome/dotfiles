# 決済バッチ遅延への対応

決済バッチは朝6時までに完了する状態にできる。追加で必要なものは、為替レートの前日取得を本番で有効にする設定変更1件だけ。

## 原因

決済バッチの実行中に為替レートAPIを呼んでおり、その応答が遅い日にバッチ全体が遅れる。

## 対応

| 項目 | 内容 |
|---|---|
| 変更 | 為替レートを前日22時に取得して保存し、決済バッチは保存済みのレートを使う |
| 満たすべき状態 | 決済バッチの実行中に外部APIを呼ばない |
| 前日取得に失敗した場合 | 決済バッチの開始前にアラートを出し、手動で再取得する |

## リスク

| 何が起きたら困るか | どう検知するか | 発生確率の見立て |
|---|---|---|
| 前日取得のレートが当日の取引に使われ、差額が出る | 経理の日次照合で差額が出る | 低い。社内規程で決済レートは前日終値と定められている |

## 参考

- 対象外: 決済バッチ全体の並列化(実行時間の主因ではないため)
- 前日取得の所要時間は検証環境で12秒だった
